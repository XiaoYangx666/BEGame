# 实战教程-惊天旷工团(2)

上章教程中，我们搭建了等待大厅，并完成了选队功能等。本章我们将完善游戏启动时所需的核心数据结构，包括**地图信息**、**队伍配置**与**游戏上下文（context）**。这些都是后续实现游戏逻辑的基础。

## 游戏地图

为了定义游戏地图，并方便后期配置、切换地图，我们先定义一个接口：

```typescript
//map.ts
export interface BlockedInCombatMap {
    name: string; //名字
    region: CubeRegion; //地图区域
    loadingPos: Vector3; //加载时玩家等待位置
    spawnPoints: Vector3[]; //队伍出生点
}
```

接着，我们创建一个示例地图并导出：

```typescript
const standardMap: BlockedInCombatMap = {
    name: "标准地图",
    region: new CubeRegion(
        DimensionIds.Overworld,
        { x: 846, y: -59, z: 958 },
        { x: 801, y: -45, z: 913 }
    ),
    loadingPos: { x: 823.39, y: -43.0, z: 935.96 },
    spawnPoints: [
        { x: 837, y: -53, z: 949 },
        { x: 837, y: -53, z: 922 },
        { x: 810, y: -53, z: 949 },
        { x: 810, y: -53, z: 922 },
    ],
};

export const BlockedInCombatMaps = [standardMap];
```

## 扩展 context

在游戏过程中，我们需要访问地图、队伍和配置等信息，因此要在 context 中扩展这些数据的存储能力。

```typescript
//context.ts
export class BlockedInCombatContext extends GameContext {
    readonly map: BlockedInCombatMap;

    constructor(map: BlockedInCombatMap) {
        super();
        this.map = map;
    }
}
```

现在 context 中可以存储地图信息了，但是还缺玩家信息。

接下来定义队伍相关的数据结构。

## 定义队伍数据

```typescript
//interface.ts
//队伍颜色
export type BlockedTeamColors = "red" | "blue" | "green" | "yellow";

//队伍数据
export interface BlockedTeamData {
    color: BlockedTeamColors; //队伍颜色
    spawnPoint?: Vector3; //出生点（稍后会随机分配）
}

/**游戏配置项 */
export interface BlockedInCombatConfig {
    mapIndex: number; // 地图索引
    liveCnt: number; // 玩家生命数
}
```

接着在 context 中加入队伍与玩家组集合：

> teams 的每一项是玩家类型为 BlockedInCombatPlayer 的玩家组，玩家组的 data 为 BlockedTeamData。(这一块后面用到就懂了)

> groupSet 是玩家组的集合，用于批量操作多个玩家组。

```typescript
//context.ts
export class BlockedInCombatContext extends GameContext {
    readonly teams: PlayerGroup<BlockedInCombatPlayer, BlockedTeamData>[];
    readonly groupSet: PlayerGroupSet<BlockedInCombatPlayer, BlockedTeamData>;
    readonly map: BlockedInCombatMap;
    readonly config: BlockedInCombatConfig;

    constructor(
        teams: PlayerGroup<BlockedInCombatPlayer, BlockedTeamData>[],
        config: BlockedInCombatConfig
    ) {
        super();
        this.teams = teams;
        this.config = config;
        this.map =
            BlockedInCombatMaps[config.mapIndex] ?? BlockedInCombatMaps[0];
        this.groupSet = new PlayerGroupSet(teams);
    }
}
```

上述代码中，我们让 context 同时持有地图、队伍和配置信息，还修改了 map 的传递方式，现在通过 config 来传递，这更便于后续地图的切换。

## 修改 Game 逻辑

接下来要让游戏引擎能正确构造出我们定义好的 context。
这需要修改 buildContext 方法。

> 💡 `buildContext` 会在 `GameEngine` 构造时调用，此时可以访问 `playerManager` 和 `groupBuilder` 来获取玩家。

```typescript
//game.ts
export class BlockedInCombat extends BlockedInCombatModule.Engine<{
    teams: [BlockedTeamColors, PlayerGroup][];
    config: BlockedInCombatConfig;
}> {
    protected override buildContext(config: {
        teams: [BlockedTeamColors, PlayerGroup][];
        config: BlockedInCombatConfig;
    }): BlockedInCombatContext {
        const teams = config.teams.map((g) =>
            this.groupBuilder.fromGroup<BlockedTeamData>(g[1], { color: g[0] })
        ); // 将普通的玩家组转换成游戏专用的玩家组，并附带队伍颜色信息

        return new BlockedInCombatContext(teams, config.config);
    }

    override onStart(): void {
        // 在常驻根 State 中配置房间回收组件，见下方指南。
        this.pushState(BlockedLoadState); //添加游戏的第一个状态
    }

    override onStop(): void {
        //重置玩家状态
        this.context.groupSet.forEach((p) => {
            p.player.setGameMode(GameMode.Adventure);
            p.clear();
            p.runCommand("effect @s clear");
            p.player.teleport({ x: 868, y: -52.0, z: 944.5 });
            p.player.setSpawnPoint();
        });
        //重置游戏规则
        world.gameRules.fallDamage = false;
        world.gameRules.pvp = false;
        world.setDifficulty(Difficulty.Peaceful);
        //杀死所有区域内生物
        this.context.map.region
            .getEntitesInRegion({ excludeTypes: [EntityTypeIds.Player] })
            .forEach((e) => e.remove());
    }
}
```

**方法说明**

-   onStart()
    游戏开始时调用，用于初始化状态、注册监听。

-   onStop()
    游戏结束时调用（无论是正常结束还是手动终止），用于恢复规则并清理现场。
-   房间回收
    在常驻根 State 中组合 DisconnectTimeoutComponent 与 AutoStopComponent，参见[房间生命周期](../../docs/room-lifecycle.md)。

## 修改 lobbyState.start 方法

最后，我们需要修改 lobbyState 中的游戏启动逻辑：

```typescript
//lobbyState.ts
start() {
    if (!this.canStartGameByPlayerCount()) {
        this.lobbyRegion.forEachPlayer((p) =>
            p.onScreenDisplay.setTitle("人数不足，已取消")
        );
    } else {
        Object.values(this.teams).forEach((t) => t.clearInvalid());
        //修改启动代码
        Game.manager.startGame(BlockedInCombat, {
            teams: Object.entries(this.teams),//传入玩家组entries
            config: {mapIndex:0,liveCnt:3},// 指定游戏配置
        });

    }
    this.getComponent(LazyLoader).reload();
}
```

## 启动流程回顾

现在让我们回顾游戏启动的整个过程:

```ts
lobbyState.start()
    ↓
Game.manager.startGame()
    ↓
BlockedInCombat.buildContext()//系统调用
    ↓
new BlockedInCombatContext(teams, config)//buildContext中构造
    ↓
BlockedInCombat.Start()//系统调用
    ↓
BlockedLoadState 开始
```

至此，游戏成功启动，玩家与地图信息都被正确加载并存入 context，
为后续的游戏逻辑（如方块生成、结束判断等）打下了基础。
